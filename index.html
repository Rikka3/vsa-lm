Chapter 01 · Step 01

Standard Transformers hoard every token

Every attention layer appends a key and value vector per token. Long `` chains, multi-file codebases, and long chats balloon VRAM until consumer GPUs hit OOM.

Chapter 01 · Step 02

Linearly growing KV rent

At 65,536 tokens, `DeepSeek-R1-Distill-Qwen-1.5B` needs 1,792 MB of KV cache and `Llama-3.2-1B` needs 2,048 MB—just for a single conversation stream.

Chapter 01 · Step 03

Bandwidth bottleneck

Every new token must re-read that entire pile from HBM. Decode throughput drops while VRAM fills up.

Chapter 02 · Step 01

1 · GQA Un-Tying & Mix-First RoPE

Pretrained GQA donors have shared KV heads (`HKV=2`). VSA-LM projects them via learned `k_head_mix` and `v_head_mix` before applying RoPE—giving 12 independent $D\times D$ heads with zero phase drift at any length.

Chapter 02 · Step 02

2 · TPR Outer-Product Binding

k_t ⊗ v_t binds role and filler into a $D\times D$ associative imprint, paired with 4-tap/8-tap depthwise causal convolutions and a 64-token + sink local window.

Chapter 02 · Step 03

3 · Learnable Multi-Scale Decay (∂L/∂γ)

M_t = γ·M_(t−1) + k_t ⊗ v_t
Our custom Triton backward kernel computes exact analytical gradients $\partial\mathcal{L}/\partial\gamma_h$ so each head adapts its own memory horizon.

Chapter 02 · Step 04

4 · Fused O(1) Read + Split-KV Graph

y_t = (1−γ)/√D · M_t q_t
One fused Triton step reads the $D\times D$ state in $O(1)$ time, captured inside a Split-KV CUDA Graph running at 120–130+ tok/s up to 64k context.

Chapter 03 · Step 01

Why passive decay forgets early facts

In passive linear attention ($M_t = \gamma M_{t-1} + k_t\otimes v_t$), every filler token multiplies $M$ by $\gamma < 1$. After thousands of filler tokens, early numbers and passkeys fade away.

Chapter 03 · Step 02

Native Abelian Page-Slot Bank (8×4 Slots)

Every VSA layer includes 32 position-free (no-RoPE) slots grouped into 8 pages. Salience router $w_{t,m} = \sigma(\text{router}(x_t))$ stays near 0 on filler text—meaning zero decay across 32,768+ filler tokens.

Chapter 03 · Step 03

100% Parity & Surgical Page Erase

Prefix-sum accumulators $(C_{t,m}, U_{t,m}, Z_{t,m})$ give 100.00% bit-level parity between parallel block-cumsum training and $O(1)$ recurrent decoding, while any page can be zeroed with 0.0 cross-page residual.

Chapter 04 · Step 01

75% VSA+Slots · 25% Softmax Anchors

Every 4th layer keeps Softmax attention (with `StaticKV` or constant-RAM `StreamKV`). Three of every four layers run fixed-size VSA + Page-Slots, slashing KV growth by 74%.

Quickstart: Convert, Heal & Serve Any Model

git clone https://github.com/Rikka3/vsa-lm.git
cd vsa-lm
pip install -r requirements.txt

# 1. Surgically convert any HF donor into VSA-LM (Page-Slots + Mix-First RoPE + 64-tok SWA)
python -m vsa_lm convert --donor deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B \
    --out deepseek_vsa_init.pth --hybrid-every 4 --max-T 2048

# 2. Heal with Stage-1 Attention Transfer + Stage-2 Binder KD + Stage-3 Teacher-Chains
python -m vsa_lm heal --ckpt deepseek_vsa_init.pth \
    --donor deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B \
    --out-prefix deepseek_vsa --tokens 60000000 --lr 1.5e-4 --kd 0.9 --highspeed
python -m vsa_lm onpolicy --ckpt deepseek_vsa_latest.pth \
    --donor deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B --chain-source teacher --rounds 3

# 3. Verify 9/9 readiness & serve with constant-RAM streaming
python -m vsa_lm hubcheck --ckpt vsa_deepseek_r1_qwen_1.5b.pth --stream-window 8192
python -m vsa_lm serve --ckpt vsa_deepseek_r1_qwen_1.5b.pth --stream-window 8192 --port 8000
